Variant ACalm chrome

Zero structural change — same columns, same widths, same markup. This is only colour, weight and hairline work. If you ship one thing, ship this: it is the cheapest diff and it does most of the visual lifting.

  • Header band goes transparent. The --surface-2 fill made the card read as two stacked objects. One surface, one rule underneath.
  • Ticker drops 700 → 600. The calm-expensive look is largely the absence of 700 text — and your own system already says so.
  • Row rules go to a real hairline (color-mix(--border 55%, --surface)). Separation comes from row rhythm; the lines just keep the eye on track.
  • Empty cells recede. The — placeholders drop to 40% so you stop counting dashes on open positions.
  • Money leads, R supports. Both were 600 in the same green; R steps to 500/0.78rem so the pair reads as one fact, not two.
  • Mute LONG to grey. Rejected. Direction keeps the active accent (long) and danger red (short) — greying it drained the row of its only quick colour cue.
  • Row hover becomes visible. #fafafa on #ffffff is a 2% delta; a 4% accent tint is legible and ties hover to the theme.
  • Fade actions to 50% until hover. Rejected. Ghosted controls read as broken, not calm. The bordered track stays at full strength; the noise is solved by removing the ⋯ where no action exists instead.
Variant BA + column rhythm

Adds the structural moves. The big one is closing the void: Status currently floats mid-row with ~400px of nothing on either side, so a closed trade looks like a half-empty row.

  • Numeric columns group. Entry/Stop are what you did; Realized/R are what happened. A 26px gap plus one header-only hairline marks the seam — no full-height grid lines.
  • Next absorbs the slack. width: auto on the Next column so the free space lands where content can use it.
  • Status right-aligns against Actions. State and controls become one cluster; the row now reads left-to-right as identity → numbers → plan → state.
  • Badges go outline. Soft-filled pills read as buttons. A 1px tinted outline says "state" and stops STOPPED OUT from being the loudest thing on screen.
  • No phantom ⋯ on closed rows. There is nothing to trim on a closed trade, so it does not render there at all. Where it does render it stays fully visible — no hover gate.
Variant CA + B + air — the recommendation

Same as B plus the spacing pass. Rows go 13px → 15px, content stops kissing the 16px card radius, and the toolbar settles onto one height so the filter pills, the date fields and Export read as a single row of controls instead of three sizes of thing.

  • Row padding 13 → 15px. With a two-line ticker cell the old rows were dense for a table you stare at; this is ~4px per row, not a redesign.
  • 20px outer gutter. First and last cells were 14px from a 16px radius, so content visually collided with the corner curve.
  • One toolbar height (30px). Date fields keep their 12px radius (they're inputs, pills are pills) but match the pills' height and the Export button's.
  • Footer earns its numbers. Values in ink at 600, labels and separators muted — the summary line is the most-read text on the page and it's currently uniform grey.
Variant DC + the three gaps

Everything in C, plus the items the checklist caught that pure styling can't fix. Scroll inside the table below to see the header pin — the frame is bounded here only so the behaviour is visible in a mockup; in the app the page scrolls, not the container.

  • Header pins on scroll. Lift the rule straight off .compound-th. Two things fall out of this: a sticky header cannot be transparent — rows scroll through it — so A1 is wrong as written. Use --surface (the card's own colour) instead of --surface-2: identical "one surface" result, and sticky-safe.
  • Collision to resolve first. .float-bar is position: fixed; top: 12px; z-index: 60 and horizontally centred — exactly where a top: 0 sticky header lands, and it appears under the same condition (you scrolled). Either offset the header to clear it, or suppress the float-bar while the header is pinned. Your call; I didn't pick one.
  • Search. 30px field, same 12px input radius as the date fields. Per your own tip, it should reach every data point — ticker, direction, status label, notes, and the sell-plan text — not just a ticker prefix match.
  • Click-to-sort headers with aria-sort and a chevron that's ghosted until hover, solid in accent when active. Full header cell is the hit target.
  • The snag in sorting. The sort you'd want most is by entry date — and entry date has no column. It lives inside the ticker cell as LONG · Aug 11. So either the Ticker header secretly sorts by date (bad), or the date gets promoted to its own column, which costs horizontal room the row does not have. Worth deciding before any of this gets built.
  • Mobile gets a rethink, not just a scrollbar — see below.
Variant D4Under 620px

Horizontal scroll is a legitimate answer and you already have it — but eight columns on a phone means the ticker is the only thing on screen. One card per trade: identity and state on top, the four numbers as a 4-up strip, the action you'd actually take on the bottom row.
